---
title: Server-side collection (beta)
description: Count AI agents and robots that request your pages without running the script
---

AI agents and robots request your pages without running the script, so the script cannot count them.
With server-side collection, `trackRequest` reports each page request your Next.js server receives to Simple Analytics, which decides whether an AI agent, a robot or a person made it.
Requests from people are discarded, because the script already counts them.

<Callout title="Beta">
  AI agents appear in your reports and count toward your usage. Robots stay hidden by default and do not count toward your usage.
  The beta covers how we classify and show this data.
</Callout>

## Set it up with an AI agent

Using Claude Code, Codex, Cursor or another AI agent?
Ask it, with your website's hostname in Simple Analytics instead of `example.com`:

```txt
Set up Simple Analytics server-side collection for example.com, follow https://docs.simpleanalytics.com/server-side-collection.md
```

The guide has the agent use `trackRequest` from this package, ask you which query parameters to report, and test the setup without storing anything.

## Set it up yourself

<Steps>
<Step>

### Set the environment variables

Server-side collection is off until you turn it on.
Set these environment variables for your production deployment, and remove the second one to turn it off again:

```txt title=".env"
SIMPLE_ANALYTICS_HOSTNAME=example.com
SIMPLE_ANALYTICS_SERVER_SIDE_COLLECTION=1
```

</Step>

<Step>

### Call `trackRequest` in your proxy

Add `trackRequest` to `proxy.ts` (`middleware.ts` before Next.js 16), next to your project's `app` or `pages` folder.
If the file already exists, add the `event.waitUntil` line to the top of its function.

<Tabs items={['Next.js 16 or later', 'Next.js 15 and earlier']}>
<Tab>

```ts title="proxy.ts"
import { type NextFetchEvent, type NextRequest, NextResponse } from "next/server";
import { trackRequest } from "@simpleanalytics/next/server";

export function proxy(request: NextRequest, event: NextFetchEvent) {
  event.waitUntil(trackRequest({ request }));

  return NextResponse.next();
}
```

</Tab>

<Tab>

```ts title="middleware.ts"
import { type NextFetchEvent, type NextRequest, NextResponse } from "next/server";
import { trackRequest } from "@simpleanalytics/next/server";

export function middleware(request: NextRequest, event: NextFetchEvent) {
  event.waitUntil(trackRequest({ request }));

  return NextResponse.next();
}
```

</Tab>
</Tabs>

`event.waitUntil` lets the page respond without waiting for the report.
If your file has a `matcher`, make sure it matches every page you want counted.

</Step>
</Steps>

## What it reports

- Only `GET` requests. It skips stylesheets, JavaScript, images, fonts, audio, video and JSON by their path, and the paths the plugin uses for the script.
- The hostname you set, the path, and only these query parameters: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `source`, `medium`, `campaign`, `content`, `term` and `ref`.
- The request headers `User-Agent`, `Referer`, `Accept`, `Accept-Language`, `Sec-Fetch-Mode`, `Sec-Fetch-Dest`, `Sec-Fetch-Site`, `Sec-Fetch-User`, `Sec-CH-UA`, `Signature-Agent` and `From`, and the address headers `X-Forwarded-For`, `CF-Connecting-IP` and `True-Client-IP`. Simple Analytics uses addresses in memory only and never stores them.
- Never cookies or authorization headers.

It runs before Next.js answers, so it does not know the response: pages that do not exist are reported too.
It sends from production deployments only, gives up after 2 seconds, never retries, and never throws.

<Callout title="Pages that are not reported" type="warn">
  Pages that a CDN or cache in front of your Next.js server answers never reach your proxy, and a static export (`output: "export"`) has no server to run it.
</Callout>

## Options

| Option                 | Default                                                    | Description                                                                   |
| ---------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `request`              | Required                                                   | The request your `proxy` or `middleware` function receives                    |
| `hostname`             | `SIMPLE_ANALYTICS_HOSTNAME`                                | The hostname of your website in Simple Analytics                              |
| `serverSideCollection` | `SIMPLE_ANALYTICS_SERVER_SIDE_COLLECTION` is `1` or `true` | Turns server-side collection on or off                                        |
| `allowParams`          | `[]`                                                       | Query parameters to report besides the ones listed above, such as `["gclid"]` |
| `testMode`             | `SIMPLE_ANALYTICS_TEST_MODE` is `1` or `true`              | Asks Simple Analytics to store nothing and prints its reply                   |

## Test mode

Test mode checks your setup without storing anything, also on your own computer.
Start your app with test mode on:

```bash
SIMPLE_ANALYTICS_SERVER_SIDE_COLLECTION=1 SIMPLE_ANALYTICS_TEST_MODE=1 npm run dev
```

Request a page the way an AI agent does:

```bash
curl -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko); compatible; ChatGPT-User/1.0; +https://openai.com/bot" http://localhost:3000/
```

Your server console then shows what was sent, including the addresses, and the reply from Simple Analytics, which explains what it would store.

<Callout type="warn">
  Turn test mode off when you are done: while it is on, nothing is stored and visitors' addresses appear in your server console.
</Callout>
